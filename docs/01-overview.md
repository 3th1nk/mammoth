# 01 · 项目定位与能力总览

## 1. Mammoth 是什么

Mammoth 是一个**自包含的裸金属服务器(bare-metal)操作系统安装引擎**。它回答一个问题:

> 给我一个带外管理地址和凭证,把一台(或一批)裸金属机器变成运行指定操作系统、
> 按我声明的分区与网络方案就绪的服务器。

它的三个核心能力域:

1. **带外管理(Universal BMC Operations)** — 开机/关机/重启、引导设备设置、虚拟介质挂载/卸载、
   KVM 控制台,统一封装为与安装流程解耦的通用 API。
2. **硬件盘查(Inventory)** — 不进入安装流程即可获取机器的硬件规格(磁盘/网卡/CPU/内存)与
   **磁盘分区布局**(分区表/文件系统/挂载点),供用户在安装前做出保留数据的决策。
3. **声明式安装(Provisioning)** — 用户以声明式意图描述"装什么、怎么分区、网络怎么配",
   引擎负责渲染、校验、引导、执行与结果回报,支持批量与失败重试。

## 2. 形态:纯后端服务

Mammoth **只交付后端服务**,不包含、也不计划包含 Web UI:

- 对外接口是 OpenAPI 3.1 契约定义的 REST API,SDK 由契约生成;
- 交互密集场景由 CLI 承担(批量提交、进度跟踪);
- 事件流(SSE/Webhook)满足集成方构建自己的界面的全部数据需求。

这是裸机管理领域的成熟形态:Ironic、Metal3 的核心均为无 UI 的 API 服务,界面由上层平台
(如 OpenStack Horizon、Cluster API 生态)独立构建。Mammoth 遵循同一分层:
**引擎保持纯粹,界面属于集成方**。

## 3. 一次典型交互

```
1. 注册机器
   POST /api/v1/machines {bmc: {address, credential_id}}
   → 引擎自动盘查:Redfish 读硬件规格,若提供 SSH 凭证则同时抓取分区布局快照

2. 用户决策
   GET /api/v1/machines/{id}
   → 返回硬件规格 + 分区快照(带 captured_at),用户据此声明分区方案

3. 批量安装
   POST /api/v1/jobs
   {
     "type": "install",
     "targets": {"machine_ids": [...]},
     "spec": {"image": {...}, "storage": {...}, "network": [...]}
   }
   → 202 + job_id;进度经 GET /jobs/{id} 或 SSE 事件流跟踪

4. 完成
   job.succeeded;机器以声明的网络配置可达,凭 access 块约定的方式登录
```

## 4. 设计原则

| 原则 | 含义 |
|------|------|
| **最小外部输入** | 机器进入系统只需要带外地址与凭证;其余信息引擎自己发现。不要求任何外部资产库 |
| **声明式意图** | 分区与网络以"意图"描述(select 规则 + 保留策略),而非预编译的精确指令;执行时现场解析与校验 |
| **介质与机器解耦** | 引导介质通用化(按架构常驻),个性化数据在运行时注入;不为单台机器定制介质 |
| **一切皆异步任务** | 所有 BMC 操作与安装均走统一的 job/task 状态机:可查询、可取消、可重试、可观测 |
| **安全默认** | 凭证只写不可读;root 口令默认按任务随机生成;快照漂移检测默认开启 |
| **边界克制** | 引擎不越界做下游系统的事(见 §5) |

## 5. 明确不做什么

边界清晰是开源引擎被集成的前提。以下能力**有意不提供**:

| 不做 | 理由 | 归属 |
|------|------|------|
| IP 地址分配/IPAM | 引擎按用户声明的地址做静态配置,不管理地址池 | IPAM 系统 |
| 权威资产管理 | `machine` 注册表是工作缓存与安装上下文,不是资产权威源;用户如果已有资产系统,以引擎 API 为适配层 | CMDB/资产系统 |
| Web UI | 见 §2 | 集成方 |
| 镜像分发 CDN | 镜像以 URL 引用;大规模分发交给制品库/对象存储 | 制品库 |
| 裸机分配/回收全生命周期 | 本引擎专注"安装"这一段;租期、调度、计费不在范围内 | 云管平台 |

## 6. 术语表

| 术语 | 含义 |
|------|------|
| BMC | Baseboard Management Controller,服务器主板上的带外管理控制器 |
| Redfish | DMTF 的带外管理 REST API 标准,现代服务器的标配 |
| IPMI | 经典带外管理协议,Redfish 普及前的事实标准 |
| 带内(inband) | 通过业务网络、在操作系统层面访问目标机器(如 SSH) |
| 盘查(probe/discover) | 采集机器硬件与磁盘布局信息 |
| layout 快照 | 某时刻磁盘分区布局的持久化记录(含 captured_at),保留分区决策的依据 |
| Install Spec | 安装意图的数据契约:image + storage + network + identity + access + scripts |
| 应答文件(answers file) | 发行版安装器的自动化配置文件(kickstart/preseed/autoinstall/unattend) |
| job / task | 批量操作 / 单机子任务;task 按 stage 推进状态机 |
